# Charles Cloud Monitor V1

用户已确认 2026-09-29 的方案。实施于当前目录，单机运行、只读采集，每 60 秒更新，保留 7 天历史。

## 范围与判定

- 区域 ms-sc-01，工作空间 modeltoolchain。
- CCI / ACP 使用当前 IAM 用户的任务范围，显示名称包含 charles 且运行中才进入主列表。名称相同的任务以平台 ID 区分。
- 每个任务展示 CPU、GPU、内存、显存数据，保留实例/worker 维度，聚合值明确来源。缺失数据是 null，不能伪装为 0。
- 展示标准资源所有可见集群的剩余 GPU 卡数、vCPU、内存。公共集群 NA 保持未知。
- 采集失败保留最后成功快照并标注过期。认证失败提示重新连接。无创建、停止、删除任务功能。
- 后台采集不依赖仪表盘标签页。电脑休眠或服务停止时不能继续采集。

## 架构

Python FastAPI 提供本地 HTTP 服务和采集调度。Playwright 在本机完成 IAM 登录并保持会话；优先读取已核实的控制台数据接口，必要时用浏览器加载页面并捕获其返回的 JSON。SQLite 保存归一化快照和指标。Tabler 与 ECharts 资源固定版本下载到 static/vendor，浏览器不依赖 CDN。服务仅监听 127.0.0.1，凭据和会话放 data/，禁止经 API 输出。

## API 合约

- GET /api/state 返回 status, connected, updated_at, last_attempt_at, next_run_at, interval_seconds, error, tasks, clusters, source_status。
- task 字段 id, kind (CCI/ACP), name, cluster, state, gpu_count (任务配置总卡数), replicas, url, updated_at, metrics (cpu/gpu/memory/gpu_memory 百分比或 null), series (metric/label/points 二元数组), workers。
- cluster 字段 id, name, available_gpus, available_vcpu, available_memory_gib, updated_at。
- GET /api/history?task_id=...&hours=1 返回 task_id, series。
- POST /api/refresh 触发非重叠刷新。
- POST /api/connect 打开本地专用登录浏览器，用户可自行 IAM 登录。凭据不经前端保存。

## 实施步骤与验证

1. 核实认证、任务列表、监控和资源余量的真实请求与响应字段。仅在 data/ 内保存必要且不含认证秘密的调试资料，代码不依赖静态示例。
2. 先写 tests/test_domain.py，验证 contains 过滤、运行状态、任务唯一性、NA 与 0 区分、CPU/GPU 单位、worker 聚合和时间戳；运行 .venv/bin/pytest，确认缺失实现失败，再实现 server/domain.py。
3. 实现 server/collector.py 与 server/auth.py，源站请求限定已知域名和只读接口。实测一次采集对照控制台，验证 5 个目标任务、worker 曲线及集群余量。
4. 实现 server/store.py 和 server/main.py，测试失败保留旧快照、7 天清理、刷新互斥、同源控制和私密文件不可访问。运行后端测试。
5. static/index.html、static/app.js、static/style.css 做中文仪表盘，包含任务筛选、状态、新鲜度、图表、集群表、空状态和登录提示。浏览器检查桌面及窄屏，处理请求失败。
6. run.sh、setup.sh、README.md、固定依赖、开源许可证及本地后台启动说明。最终做真实采集、API、浏览器与自动测试联合验证。
