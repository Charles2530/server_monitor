## 排查证据

- 远端目录列表读取为 1–3 毫秒；未发现 CPU 持续饱和。不能据此排除所有间歇性远端负载。
- 通过实际 SSH/WebSocket 测到往返通常约 350–450 毫秒。目录展开和用户文件读取仍需远端操作。
- 编辑器内置语法文件经 `vscode-remote-resource` 加载；旧规则不覆盖该路径。几百字节的图标也会付出多次网络往返。
- 浏览器自动追加空 `tkn=`，早期候选规则因此仍漏过资源。最终规则只归一化单个空占位符，真实令牌、重复参数和未知参数继续绕过缓存。
- Markdown 预览的版本化 index.html、fake.html、service-worker.js 属于固定启动资源。远端探针验证 index.html 在不同 id、parentOrigin 参数下 SHA256 完全一致。
- 首次观察到的某次长时间无响应恰逢其他任务重启生产服务，已排除，不计为正常性能样本。后续均在隔离端口 8876 测量。

| --- | ---: | ---: | ---: |

| 图标 | 1535.61 ms | 20.31 ms | 11 / 11 |

上述新会话样本含一个 `.tmLanguage` 文件名带空格/括号的漏网请求，耗时 731.78 ms。最后补丁已支持该实际观测路径，新增回归测试先失败后通过；该最后一项格式扩展尚未重新做远端浏览器整轮计时，因此不推算额外提速。

## 修改范围

- `server/ide_assets.py`：受信任安装根目录内的版本化资源缓存；兼容空 tkn、`.tmLanguage` 文件；精确允许三种 webview 启动资源；保留 CSP。

用户工作区文件、动态 HTML、预览内容和认证数据不缓存。保持原有每站点隔离、32 MiB 单资源、128 MiB 总量及 512 条目的上限。未改变用户远端设置、未禁用扩展、未改动远端项目文件。
