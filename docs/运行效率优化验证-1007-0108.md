# 全站运行效率优化验证

2026-10-07，北京时间。已更新本机运行服务。

## 修改

- 后台采集：监控元数据与任务、队列、集群列表并行读取。指标仍等待元数据；继续使用既有并发限制、鉴权处理和取消清理。
- 主状态轮询：历史曲线请求独立完成，较慢的历史响应不再占住主状态刷新。相同历史请求合并、过时响应丢弃等行为保留。
- 主状态接口：对已规范化的快照直接返回 JSONResponse，省去一次递归类型转换，字段过滤与缓存策略保持一致。
- TokenHub、存储、任务历史、队列与日志：复用日期格式化器；TokenHub 金额、用量与存储容量复用数字格式化器。日期口径、金额精度、零与未知显示经过验证。

## 局部基准

以下均为本机模拟数据基准，不使用真实云任务写操作，不代表全站或公网端到端同比例提速。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 冷元数据与独立列表各模拟等待 40ms，7 次中位数 | 84.676ms | 43.467ms |
| 1,000 个模拟任务的主状态响应，交替运行新旧实现并预热后取中位数 | 27.022ms | 15.130ms |
| 2,000 个北京时间日期格式化，7 次中位数 | 57.305ms | 2.156ms |
| 2,000 个费用金额格式化，7 次中位数 | 25.112ms | 0.765ms |

状态响应在新旧实现之间逐字节相同，均为 512,103 字节。元数据已有缓存时，不预期获得上述冷读取收益。原有数据库保存及历史查询基准保留，用于检查运行环境；本轮未修改数据库写入或查询算法，不将其计时波动归因于本次优化。

格式化基准可复现：

```sh
MONITOR_FORMAT_BENCHMARK=1 node --test --test-reporter=spec --test-name-pattern='formatting benchmark' scripts/frontend_efficiency_check.js
```
