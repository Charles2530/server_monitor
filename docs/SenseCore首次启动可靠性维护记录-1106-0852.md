# SenseCore 首次启动可靠性维护记录

新建 CCI 容器首次打开 VS Code 时，后台插件安装遇到慢下载或控制连接中断，现在会核对容器实际状态并有限重试，页面持续显示进度。已有编辑器进程、端口和浏览器内容继续复用。

## 原因与改动

- 固定版本 Codex VSIX 为 249,969,698 字节。此前观测到仍在下载的进程约 245.9 秒后触发 240 秒总下载限制；下载预算调整为 420 秒，网络异常最多三次尝试，保留大小和 SHA256 校验。
- SenseCore 自动导入的代理可在网络异常重试时使用独立直连 opener；手动指定的下载代理及容器已有代理继续生效。
- 新增只读容器状态脚本，核对实际安装结果、安装锁及安全进度；不读取认证内容，不下载、写设置或启动进程。
- 快速打开路径遇到安装锁时复用健康编辑器，不排队等待整套插件安装。进度仅由持锁安装任务原子写入，控制连接断开后可继续读取。
- 后台流程先核对再安装；远端仍在安装则等待，控制连接中断后继续核对；每轮最多三次安装、三次连续探测失败和 30 分钟总预算，关闭会话取消本地恢复链。
- 增加绑定插件集合版本的配置完成标记。重配置前撤销旧标记，Python、格式化、性能及语言配置全部成功后才原子写入，避免文件下载齐全却误报准备完成。
- 页面区分核对、安装、退避和失败，持续轮询到流程完成；失败提示明确五分钟冷却，状态更新不重载 iframe。
- 控制脚本只压缩一次，移除传输中无需执行的文档字符串及注释，保留既有 20 KB 快速启动载荷限制。

修改文件为 `server/ide_codex.py`、`server/ide_bootstrap.py`、`server/cci_ide.py`、`server/ide_extensions.py` 和 `static/ide.js`。

## 维护边界

全新安装验证使用隔离目录和模拟进程；线上验证使用已有容器，未新建付费服务器。实际下载仍依赖容器网络，持续失败后会显示暂停及重试提示。运行副本同步会重启本机监控服务；本次未重启远端编辑器。回退时可撤销本次源码提交并重新同步，本次新增的配置标记可由旧版本忽略。

测试源码按仓库现有 `.gitignore` 规则保留在本地。原实施计划保留于 `docs/superpowers/plans/SenseCore首次启动可靠性实施计划-1106-0831.md`，其中步骤 1–5 已完成。
