# Terminal 与 Codex 加载优化

本轮已完成代码、独立环境验证与发布包准备。本文生成时尚未切换正在运行的监控服务；重启前需确认当前编辑内容已保存。

## 已确认原因与修改

| 问题 | 证据 | 修改 |
| --- | --- | --- |
| Codex 反复出现 Continue | 已安装插件 26.5908.31748 的欢迎页将确认写入 VS Code globalState；浏览器版存储由 IndexedDB 管理。同一地址刷新保留确认，更换随机端口再次出现欢迎页。 | 按站点、任务、实例、容器、父页面地址和容器地址保存独立端口。跨代理进程重开复用地址。 |
| 加载过程中连接被替换 | 独立实机诊断在触发修复前 0.16 秒仍收到上游数据，两个通道累计约 22 MB；22.87 秒后通道被替换。 | 心跳超时判断同时参考最近收到的数据与确认 pong。持续上游传输可保留连接，真正静默仍修复。 |
| 健康检查额外下载页面 | 原实现 GET 会读取完整 HTML，错误状态的响应体异常还会混入网络异常判断。 | 仅读取响应头并关闭响应；401/403/500 和登录跳转始终判失败。 |
| Terminal 小块输出回调过多 | 同一 64 KiB 响应包含 4096 个小块，原来逐块等待 xterm 回调。 | 同响应内合并为不超过 64 KiB 的批次，测试中 4096 次回调降为 1 次。 |

固定端口注册表使用文件锁和原子保存。端口已占用、注册表损坏时明确失败，不转用其他工作区的地址；锁等待最多 2 秒。新会话仍轮换认证 cookie 和入口票据，原会话凭据失效。

Terminal 保持字节、UTF-8、ANSI 顺序，最后写入回调完成才推进 cursor／ACK；保留取消和关闭语义，未改输入重放协议。

- 最终运行目录候选快照：650 项 Python 测试通过，5 条已有 websockets 弃用警告。
- 精确候选前端：20 项 Node 行为测试通过。
- 独立复审验证实际 xterm 的 UTF-8／ANSI、异步解析暂停及错误行为；修复文件锁无期限等待、错误响应体异常掩盖状态这两个审查问题。

## 限制与回滚

首次启用固定地址会建立新的浏览器存储空间，因此可能仍需确认一次欢迎页；后续同工作区、同浏览器、同网站地址重开会复用。换浏览器、清空网站数据或换容器后重新出现引导属于新的存储空间。

本次未改 Codex 插件代码、登录文件、权限模式或审批设置。官方文档检索未返回可用内容，欢迎页判断依据是实际安装包源码和真实页面。

Codex 自带多个大资源包，实测仍出现云端 1006／连接波动。本轮解决了重复冷启动和已复现的活跃连接误判；不能保证固定加载秒数或宣称所有卡顿消失。

独立 HTTP 未压缩资源的 SSH 压缩对照不代表聊天链路：实际 WebSocket 已协商 permessage-deflate，因此未据此增加第二层压缩。

回滚使用本地发布工具恢复备份代码；新增 SQLite 索引可保留，不覆盖实时数据库。发布工具与原始诊断保存在忽略的 data 目录，不上传凭据或聊天截图。
