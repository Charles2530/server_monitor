# TokenHub 接入实施计划

目标是在资源总览显示 TokenHub 摘要，并增加独立的侧边栏详情页。使用已核实的本站登录令牌及刷新接口，与 GPU 站点的 IAM 会话隔离。

## 实施范围

1. `server/tokenhub_auth.py` 保存本站 access/refresh token 到 `data/tokenhub/session.json`（目录 700、文件 600）。首次由用户在独立浏览器完成 GitHub 登录；仅保存 TokenHub 令牌，不保存 GitHub 密码和浏览器 Cookie。续期串行执行并原子保存旋转后的令牌。
2. `server/tokenhub.py` 固定访问 `https://tokenhub.ilab.beer/api/v1`，提供账户、统计、平台额度、订阅、Key 元数据及用量读取。返回字段白名单，不转发账户登录令牌、Key 明文、请求内容、上游异常正文。每部分单独记录更新时间，失败保留旧数据并标注。
3. `server/tokenhub_routes.py` 注册本地固定路由，沿用 Host、Origin 和写请求标记检查。连接及断开仅在本机可用；手机允许读取经过脱敏的数据。TokenHub 账户为全局，不随 GPU 站点切换。
4. `static/tokenhub.js`、`static/tokenhub.css`、`static/index.html` 和 `static/navigation.js` 增加总览摘要及 TokenHub 页。页面包含平台额度、用量明细、Key 列表、订阅及原站管理入口。自动刷新间隔 60 秒，仅在相关页面读取。
5. 用户已选择“先只查看详情，管理操作跳转原站”。只提供只读详情与原站管理入口，不修改远端 Key。

## 数据口径

- 账户余额和平台额度保留美元单位；不换算成剩余 token。
- 日、周、月平台额度分别展示，未设置限制、禁用、未知不能当作零余额。
- 已用量缺失时剩余额度为未知；已用超过上限时剩余为零并标出超额状态。
- 用量明细支持日期范围和分页；日期以亚洲上海时区的自然日初始化，并向原站传其支持的 timezone 参数。
- Key 列表显示名称、状态、分组、额度、到期时间；不显示原始 Key。

## 验证顺序

- 先在 `tests/test_tokenhub.py`、`tests/test_tokenhub_api.py` 写回归断言并观察失败。
- 使用 httpx MockTransport 验证 401 续期并发、轮换保存、超时及异常脱敏、未知额度、部分失败、分页与日期校验。
- 修改后运行新测试及已有 API、导航、移动网关测试；再运行后端全量 pytest。
- 使用本地模拟 HTTP 数据验证桌面和 390/360px 移动布局、导航唯一活动页、读取失败保留旧值、XSS 文本、分页筛选。
- 实际登录后只做读取验证，不触发远端 Key 创建、编辑、删除或消费。

## 交付边界

本站没有承诺公开稳定 API，接入依赖当前页面使用的接口；接口改变时显示错误，不能继续显示为正常更新。用户未完成首次登录时，交付可用的连接入口及已验证的模拟流程，并明确真实账户尚未验证。代码更新后沿用项目部署脚本更新本机运行副本，保留既有会话与数据。
