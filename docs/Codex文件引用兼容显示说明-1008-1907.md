# Codex 文件引用兼容显示

## 结果与范围

本项目打开的 VS Code 网页编辑器中，普通文件引用压缩为 28px 高的一行标签，显示小图标、文件名和原生移除按钮；多文件继续使用原生横向滚动。悬停显示完整文件名，已有原生提示优先保留。图片和有实际预览内容的附件不压缩，历史消息也不改变。

该方案不改写 Codex 安装文件，不依赖版本号、打包哈希、资源文件名或压缩后的函数名。桌面版 VS Code 不经过本项目代理，因此不在此次生效范围内。

## 修改文件

- `server/ide_proxy.py` 只在 openai.chatgpt 的 VS Code webview 外壳中加载适配脚本，保持现有鉴权和 CSP，不修改插件 JavaScript、CSS 或消息内容。外壳和适配脚本禁用持久缓存。
- `static/editor-appearance/codex-files.js` 通过 webview 内层文档加载构造式样式表，识别输入区里已核实的附件结构。React 更新或 iframe 重建时重新检查，不替换任何原生控件或事件处理器。
- `static/editor-appearance/codex-files.css` 调整普通文件标签的尺寸和排版，给移除按钮预留空间。

## 兼容边界

无法保证尚未发布版本的内部结构永远不变。识别失败、跨域不可访问、浏览器不支持构造式样式表、出现真实预览或上传状态时，保留原生界面。文件引用依然通过原生命令添加，适配层不接触发送数据。

版本更新只要保留已识别结构即可继续紧凑显示。大幅改版后可能恢复原生卡片，需要更新独立适配层；不需要修改插件安装包。

## 验证

- 三项代理接口测试通过，覆盖 gzip HTML 注入、缓存处理、其他扩展与资源不改写、脚本鉴权和方法限制。
- 从 26.5908.31748、26.623.141536、26.930.61225、26.1002.51308 的组件提取原始结构，配合原 CSS，在独立无头浏览器中验证 640px 和 320px 两种宽度，共八组通过。
- 检查文件标签高度、长文件名与移除按钮不重叠、横向滚动、悬停文件名、打开与移除测试事件、文本输入、刷新恢复、图片和历史消息保持原状。
- 额外模拟未知卡片结构并确认恢复原生样式；其他扩展不应用适配。
- JavaScript/Python 语法与 `git diff --check` 通过。

这些是组件样本与代理接口验证，并非四个完整插件的端到端实机测试；尚未在当前远程编辑器会话中实测，也未重启或部署运行中的监控服务。发布前已在独立工作区重新运行代理测试，结果通过。

## 生效与回滚

部署这三个文件并重启监控服务后，重新打开网页编辑器以加载新的 webview 外壳。无需重装 Codex。

回滚只需撤销代理中的注入入口并重新打开编辑器。Codex 安装目录始终未修改，没有插件补丁或备份需要恢复。
