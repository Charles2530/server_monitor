# Android 启动修复与真机验证

## 结论

0.1.3-prototype 已通过 USB 覆盖安装到用户的一加 13T（PKX110，ColorOS 16，Android 16），完成两次冷启动和返回前台检查。网络模块启动完成，页面显示 `NeedsLogin`，等待 Tailscale 登录。没有部署电脑端，也可以正常启动 App。

这只确认启动闪退已在该手机复现并修复；Tailscale 账号登录、另一台 Mac 的配对和跨网监控尚未验收。电脑端部署仍按 [部署交接文档](手机客户端与Mac部署交接-1001-1705.md) 执行。

## 已确认的原因

旧包 0.1.1 真机启动后收到 SIGABRT。App 日志中的直接原因是：

```text
panic: no safe place found to store log state
```

固定依赖 Tailscale v1.102.5 的 `ipn/ipnlocal/local.go` 创建 socket-statistics logger 时调用 `logpolicy.LogsDir`。仅设置 `tsnet.Server.Dir` 未覆盖这个独立目录；Android App 缺少库所依赖的可写默认目录，最终触发 panic。

新代码在创建 Android 客户端之前创建私有 `no_backup/tailscale/logs` 目录，并设置进程内 `TS_LOGS_DIR`，权限为 0700。目录建立失败时返回错误；不修改手机系统目录或其他 App 配置。

该手机实测页面大小为 4096。0.1.1 补充的 16 KB 原生库对齐是兼容性修正，不是这次闪退的根因；相关构建检查继续保留。

## 附带诊断能力

原生库加载移到后台启动流程。保留启动阶段、Java 异常及原生启动日志的本地诊断入口；用户可以查看并主动复制经过脱敏的诊断文本。网络启动成功后恢复 stderr，避免持续记录原生日志。

诊断功能不自动上传内容。0.1.2-diagnostic 是排查用包；日常使用本次 0.1.3-prototype，正常打开后自动启动网络模块。

## 验证

- 旧版本在同一手机上重现 panic；修复后两次冷启动均完成，进程存活且当前进程日志无 panic。
- 返回桌面后重新进入 App，进程未更换，页面显示 `NeedsLogin`。
- Go 单元测试、竞争检查和 vet 通过；新增日志路径与失败边界回归测试。
- Android JVM 测试共 5 项通过，APK 构建和签名校验通过。
- 原生 ELF 16 KB 对齐检查通过。
- 原监控后台、云任务、手机其他应用均未修改；APK 覆盖安装保留本应用数据。
