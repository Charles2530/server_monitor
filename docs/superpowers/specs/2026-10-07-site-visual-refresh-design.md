# 全站视觉更新设计草案

状态：用户已确认美化整个网站；采用清爽专业控制台方向，已完成实施、验证和本机上线。

## 目标与现状

用户希望再次美化整个监控网站。已检查主页面结构、主题与响应式样式，并查看运行服务的资源总览和任务页。现有站点采用青绿色强调色、浅灰底色和白色卡片；需要进一步改善辅助文字对比、主次信息层级、控件一致性和密集数据的阅读体验。

## 方向选择

1. 清爽专业控制台（推荐）：延续青绿色，使用中性灰底、白色面板、清晰边界和适量留白；适合每日长期查看资源、任务和费用。
2. 深色技术控制台：强化深色底与高对比数据，视觉变化更明显；需要接受更强烈的技术风格。
3. 极简紧凑工具：减少装饰、压缩间距、提升同屏数据量；视觉较克制，更偏效率。

以下为推荐方向的具体设计。

## 全局规范

- 浅色使用冷中性灰页面、白色卡片、深灰正文和青绿色主操作；深色使用石墨灰页面、分层灰色卡片和明亮但克制的青绿强调色。
- 颜色集中为背景、面板、边线、正文、辅助文字、强调色与状态色变量，模块引用同一套语义。
- 正文与控件文字以 14px 为基准，辅助文字以 12–13px 为基准，页面标题 24–28px，主要指标 30–36px；数据采用等宽数字。
- 采用 4/8/12/16/24/32px 间距阶梯；面板圆角 12–16px，控件圆角 8px；边框和轻阴影分离层级。
- 桌面常规控件高度 36–40px；手机主要点击目标至少 44px。统一选中、悬停、键盘焦点、禁用和加载状态。
- 轻量颜色与阴影过渡，尊重减少动态效果偏好。

## 页面范围

| 页面 | 调整重点 |
| --- | --- |
| 全站导航和页头 | 统一导航选中态、站点切换、主题切换、标题和操作按钮；强化当前位置 |
| 资源总览 | 四项关键数字对齐；集群表格层次清晰；TokenHub 摘要与任务速览统一面板结构 |
| TokenHub | 金额、单位、更新时间分层；统一两张费用图的面板与范围切换；优化额度卡片和用量表格 |
| 运行任务 | 优化列表和详情区比例、长任务名称展示、指标对齐与选中卡片；统一监控和日志工具栏 |
| ACP 任务 | 表单分组、标签、输入、资源选择、预览及确认弹窗形成一致的视觉顺序 |
| 队列管理 | 强化任务身份、资源要求、状态和操作的列层级，优化筛选栏 |
| 存储管理 | 统一容量摘要、查询控件、数据表格和状态提示 |
| 任务历史 | 统一统计条、筛选和分页；区分时间、标识与状态 |
| Terminal / VS Code | 统一本地页头、连接选择、连接状态、恢复按钮和工具栏；确保工作区仍获得足够空间 |

## 实现边界

沿用原生 HTML/CSS/JavaScript 和现有主题机制，以共享视觉变量及已有组件样式为主，按需做少量语义化结构调整。保持路由、关键 DOM 标识、接口和业务流程兼容。刚修复的 TokenHub 零消费显示行为纳入回归验证。

覆盖加载、空数据、未知数据、旧数据、错误和禁用状态。错误与成功均保留文字提示，不能只靠颜色区分。长名称可换行或截断并提供完整名称访问方式；表格滚动局限在表格容器。

## 验收与上线

检查 1440、1024、768、390、320px 宽度下的主要页面，验证浅色与深色，排除页面横向溢出、按钮遮挡和不可读文字。普通文本以 4.5:1 对比度为目标。

运行与改动相关的现有导航、主题、布局、TokenHub、手机和工具页面模拟验证；在浏览器中检查真实布局。涉及创建、停止、复制密钥等操作使用模拟数据验收。

上线前核对运行副本与源代码差异，备份本次修改文件，更新本机运行副本并检查页面资源和服务健康。交付说明覆盖范围、验证结果及已知限制。
