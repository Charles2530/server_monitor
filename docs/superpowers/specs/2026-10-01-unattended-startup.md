# 无人登录的 Mac 监控启动

用户明确要求重启后无需登录即可运行监控和手机连接。当前机器 FileVault 已关闭，不修改自动登录、磁盘加密、电源设置，不重建 APK，不执行云任务操作。

采用系统 LaunchDaemon，主监控、网关及已安装的飞书服务仍以原普通用户运行，沿用内置磁盘上的配置、数据库和 Python 环境。迁移前备份用户 LaunchAgent，停止原实例并移走自动启动入口，避免重复采集或发送。安装失败恢复原用户服务，支持明确的回退命令。

手机网络使用固定版本的开源 tailscaled，以 userspace networking 运行并保存独立本机状态，由系统 launchd 管理。此模式不添加系统 VPN/DNS 规则，Serve 仅在 tailnet 发布网关 8767，不启用 Funnel。首次需要同一 tailnet 的账号授权。保留官方 GUI 客户端及旧网络身份，验证新入口后再停用其自动启动；尽量保持手机原网关域名，否则协助重新配对。

对比方案：现有 LaunchAgent 无法覆盖无人登录场景；自动登录会改变 Mac 的登录保护，不采用；系统 LaunchDaemon 满足需求并可回退。管理员认证仅用于最终安装系统 plist，不能在聊天或配置中收集密码。

验证包括生成 plist 的运行用户/回环端口、迁移回退、禁止重复安装用户服务、全量测试、system 域运行及 HTTPS/手机访问。未真正重启或退出登录时，明确区分已验证系统服务运行和未完成的开机实测。
