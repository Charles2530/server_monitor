# Codex 项目聊天历史过滤设计

状态：用户已确认从 CCI 容器内的 `CODEX_HOME` 读取 session，并严格显示当前项目根目录及其子目录的聊天记录。

## 目标与边界

打开 CCI VS Code 时，Codex 历史列表只展示当前编辑器 workspace 对应项目及其子目录产生的聊天。数据源使用容器内实际生效的 `CODEX_HOME`，本机 Mac 的 `~/.codex` 只作为调试参考，不参与正常过滤。

过滤范围使用规范化后的绝对路径：`cwd` 等于当前项目根目录，或以当前项目根目录加 `/` 开头。只记录到上级目录的 session 不计入当前项目；没有项目路径的 session 默认隐藏。当前项目路径从容器内编辑器启动结果中的 workspace 值取得，不能依赖浏览器 URL 或本机文件系统。

本功能只读取 session 元数据，不读取或返回聊天正文、提示词、模型输出、Token、Cookie、认证文件内容或环境变量值。它不改变 Codex 的 session 数据，也不修改任务、容器或云端资源。

## 方案

### 容器内元数据读取

在现有 CCI 编辑器准备通道中增加一个只读的历史元数据读取动作。动作复用已验证的 CCI 目标和临时容器 shell，使用受控 Python 脚本在容器内完成：

1. 确定 `CODEX_HOME`：优先使用进程环境中的绝对路径；未设置时使用当前用户 home 下的 `.codex`。拒绝相对路径、符号链接逃逸到允许目录之外的路径，以及超出大小上限的文件。
2. 优先打开 `sqlite/codex-dev.db`，只查询 `local_thread_catalog` 的 `thread_id`、`display_title`、`source_updated_at`、`cwd` 和必要的来源字段。数据库不存在或查询不可用时，扫描 `sessions` 下有限数量的 rollout JSONL，只解析 `session_meta.payload` 中的 session ID、更新时间和 `cwd`。
3. 对路径执行容器内 `realpath` 和分隔符归一化；过滤当前根目录与子目录；按更新时间倒序、数量上限返回。
4. 只输出经过字段白名单和长度限制的 JSON 元数据。异常只返回稳定的错误代码和简短状态，不回传原始异常或文件内容。

读取动作应有短缓存，避免每次 DOM 变动都访问 SQLite；当前 workspace、容器和 `CODEX_HOME` 变化时清除缓存。

### 前端联动

编辑器代理继续注入现有 `ide-frame-status.js`。父页面在编辑器连接建立后向注入脚本发送当前 workspace 和过滤结果，脚本只在 Codex 历史界面可见时工作：

- 如果历史项暴露稳定的 thread ID，按 ID 精确隐藏不属于当前项目的项。
- 如果当前 Codex 版本没有暴露 ID，启用一个轻量的“当前项目聊天”过滤层，使用后端返回的完整元数据打开对应记录；不使用标题单独猜测归属。
- 过滤层提供当前项目路径提示、记录数量、刷新按钮和“显示未归类记录”开关；未归类记录默认关闭。
- Codex 原生列表无法识别或过滤动作失败时，保留原生历史界面，并在本站连接日志记录 `history_filter_unavailable`，不阻塞编辑器使用。

过滤状态按编辑器 workspace 与容器隔离保存，刷新页面后恢复；切换任务、容器或 workspace 时清空旧的允许列表，防止不同项目串线。

## 接口与错误处理

新增接口只允许通过本站已认证的 IDE 请求调用，并绑定 `task_id`、instance、container 与当前页面 origin。接口返回统一结构：

- 成功：workspace 标识、元数据版本、过滤记录及读取时间。
- 空结果：成功状态加空列表，前端显示“当前项目暂无历史聊天”。
- 容器不可达、CODEX_HOME 不可读、数据库格式不支持或读取超时：返回稳定错误码；前端保留原生列表并提供重试。

脚本和接口设置超时、单次输出上限、记录数量上限和字段长度上限；任何异常都必须关闭临时 shell。读取 session 不能影响正在运行的编辑器、Terminal 或 Codex 会话。

## 验证

增加脱敏单元测试覆盖：

- 根目录、直接子目录、多级子目录匹配；相似前缀目录不匹配。
- `cwd` 为空、相对路径、符号链接路径、路径末尾斜杠和 Windows 分隔符处理。
- 数据库存在、数据库缺失、数据库损坏、JSONL 回退和空结果。
- 输出字段白名单、数量及长度限制，不包含正文、Token 或认证字段。
- 任务、容器、workspace 切换后不会沿用旧过滤列表。

增加浏览器模拟验证：

- 原生历史项有 thread ID 时的精确隐藏和恢复。
- 无 thread ID 时的过滤层展示、刷新、空结果和未归类开关。
- 容器读取失败时编辑器仍能打开，连接日志有记录。
- 刷新、重新连接、自动恢复和 Codex 默认 Continue 流程不受影响。
- Terminal、VS Code 多标签页和不同 CCI 任务之间的隔离。

上线前只在测试 CCI 容器中读取元数据，核对容器内真实 workspace 与 `CODEX_HOME`，不执行任何云端写操作。
