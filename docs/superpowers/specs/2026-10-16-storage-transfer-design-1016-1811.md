# 数据传输页面视觉改版设计

## 目标

把存储管理中的“数据传输”页改成紧凑的双端工作台，解决真实节点选项较长时布局松散、浏览目录区域撑高页面、执行方式信息量不足的问题。桌面端和手机端都要保持可用，并沿用 TokenHub、镜像管理等页面已有的深色面板、绿色强调色和紧凑信息层级。

## 设计

- 顶部保留页签、标题和说明，减少重复留白。
- 源端与目标端使用桌面双列、窄屏单列的端点卡片。卡片内部统一为“端点类型 → 节点或站点 → 路径”的顺序。
- 节点类型、节点、站点和 Bucket 等选择控件使用等宽网格；长选项保持原始文本，通过控件宽度、字体和换行策略避免挤压其他字段。
- 路径输入与“浏览目录”按钮保持同一行，窄屏下自动堆叠。
- 目录浏览器限制最大高度，目录项改为紧凑网格；目录标题、返回上级和条目使用统一的辅助色与悬停状态。
- 执行方式变为独立的路线摘要卡，展示传输方向、网络入口、模式选择和执行提示，避免短内容卡片显得空。
- “开始传输”与状态消息形成独立操作区，按钮在移动端占满可用宽度。
- 传输任务空状态改为带状态标记的占位面板；有任务时保留现有进度、路径和日志逻辑，仅优化层次和密度。

## 数据与交互边界

本次只调整页面结构所需的 class、文案容器和 CSS，不改变 `/api/transfers`、`/api/transfers/executors`、`/api/transfers/browse` 接口，也不改变已有校验、轮询、取消任务和目录选择行为。现有 `storage.js` 的事件绑定通过固定 id 保持兼容。

## 响应式规则

- 宽屏：源端和目标端并列，路线摘要横跨整行，任务列表位于下方。
- 中等宽度：端点卡片保持单列，字段仍尽量双列；目录条目改为单列以保证长文件名可读。
- 手机：所有字段单列，控件最小高度 44px；浏览目录列表保持可滚动；操作按钮和状态提示垂直排列。

## 验证

- 在当前深色主题下检查真实长节点选项、已展开目录、空任务状态和错误提示。
- 切换浅色主题，确认边框、背景和文字对比度仍与全站一致。
- 在桌面与窄屏视口检查双列到单列的断点、路径输入和按钮布局。
- 运行现有前端/后端最小检查，确认数据传输页原有提交、刷新和目录浏览逻辑未被破坏。
