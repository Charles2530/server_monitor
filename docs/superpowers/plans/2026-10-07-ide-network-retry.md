# IDE 刷新网络失败修复

## 证据与范围

2026-10-07 用户报告内嵌编辑器“拒绝连接”，随后刷新显示 `Failed to fetch`。初次检查 PID 40203、8766 和 61552 均运行；再次检查主服务已变为 PID 45318，启动时间为北京时间 12:15:16，61552 不再监听。日志记录期间服务经过 PID 45176 后重启。服务恢复后重新打开入口，编辑器和 Codex 输入框恢复。

本地测试让 IDE targets 请求发生一次连接失败，旧版页面持续停留在 `Failed to fetch`；证明初始化 API 缺少断线重试。服务重启还会丢失内存中的准备请求 ID。

## 修复

只修改 `static/ide.js`：IDE API 的网络错误最多追加两次重试，间隔 1 秒、2 秒；取消后以 generation 校验阻止旧请求继续操作。离线、服务返回的权限/业务错误以及超时不进入网络重试。持续失败改为中文提示并保留重新连接按钮。状态 API 返回 `ide_expired` 时仅重新建立一次相同准备操作，持续过期则报错。现有编辑器 iframe 和草稿保护不变。

## 验证与部署

- `scripts/ide_network_smoke.py`：先复现失败，再通过 7 例，覆盖 targets/open/status 短暂断线、准备请求失效、持续断线、拒绝访问和持续过期。
- `scripts/cci_ide_smoke.py`：原有桌面入口、双站点、状态/重试、恢复、草稿保护、来源/地址验证等通过。
- Node 语法检查、`git diff --check` 通过。
- 仅部署桌面运行目录 `static/ide.js`，写前比较基线哈希，未重启服务。备份：`data/releases/before-ide-network-retry-1007/`。

此修复改善短暂中断的恢复，不阻止其他部署主动重启监控进程。持续服务不可达时仍需恢复服务或由用户手动重连。

后续用户要求已升级为完整自动修复与连接日志；参见 `2026-10-07-ide-auto-repair.md`。初始API和重建失败会继续按5至120秒退避自动尝试，网络离线期间停止。
