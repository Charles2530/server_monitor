# VS Code 预连接与主动恢复验证记录

## 结论

本轮候选完整重建到工作台可用实测为 15.6 秒、17.6 秒；后一次包含最终取消清理修复。静默传输故障恢复为 32.89 秒、31.65 秒，后一次故障发生于预连接创建的 SSH master。未保存草稿、故障后继续编辑和远程终端执行均已通过实际界面验证。

截至本报告生成，候选未部署。当前生产保留上一轮版本；生产热启动曾实测 8.6 秒、完整重建约 30 秒。新候选需要保存当前编辑内容后再切换，并继续生产验证。

## 慢连接原因与修改

此前连接流程中，远端准备与 SSH 认证串行执行，每次新建会多等待一次 SSH 握手。本轮在确认实例归属并取得准备名额后，让自有 SSH master 认证与远端准备并行；准备结束只添加指定的 localhost 转发。实际认证耗时 3.5–3.8 秒已与准备重叠，添加转发约 0.02 秒。相对于旧版约 30 秒的全部差异还包含网络波动，不能全部归功于预连接。

静默故障时 SSH 进程仍存活，旧路径依赖后续请求或较慢的 WebSocket 超时发现故障。本轮代理每 10 秒发起保活探测，8 秒未回复触发合并的恢复检查；仅探测超时不会主动断流，仍用带认证的 HTTP 确认是否需要重建。单个探测保持唯一，慢响应不会堆积任务。恢复保持原代理地址和页面，使浏览器里的未保存文本留在原编辑器中。
