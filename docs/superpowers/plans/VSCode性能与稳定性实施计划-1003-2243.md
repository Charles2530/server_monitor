# VS Code 性能与稳定性实施计划

**目标**：优化已有 CCI 浏览器编辑器，缩短进入时间，保留未保存内容，网络和 SSH 故障后自动恢复。不能承诺在断网或容器销毁时维持真实在线，验收以可观测恢复行为为准。

**架构**：保留 localhost 独立编辑器端口及现有认证。固定版本的只读静态资源由站点隔离的本机磁盘缓存提供；任务、工作区、认证和插件动态资源不缓存。健康会话走复用路径，重建连接仍核验当前任务身份。故障恢复保留代理端口、浏览器 cookie 和 iframe。

**技术栈**：Python asyncio、HTTPX、FastAPI、SSH、code-server、浏览器 JavaScript。

## 已验证基线

2026-10-03，同一已运行的 2 卡 CCI 容器。首次进入后台准备 34.7 秒，工作区出现 106.2 秒；连续再进入后台准备 11.5 秒，工作区出现 19.8 秒。首次 workbench.js 压缩传输约 4.9 MB，耗时 64.5 秒。当前 49 项 IDE 测试通过但未覆盖实际加载性能。

参考站点 ksp.console.ksyun.com 跳转到金山云登录页，未核实其内部代理、缓存或保活实现，不据此声称采用相同架构。

## 执行步骤

- [ ] 资源缓存。新增 `server/ide_assets.py`、`tests/test_ide_assets.py`，接入 `server/ide_proxy.py`、`server/cci_ide.py`。先证明新代理仍会访问上游，再实现固定 commit 静态资源缓存。覆盖鉴权、跨端口/对象复用、压缩、路径限制、动态内容排除、不完整传输、磁盘和容量故障。运行 `.venv/bin/python -m pytest -q tests/test_ide_assets.py tests/test_ide_proxy_http.py tests/test_cci_ide.py`。
- [ ] 连接准备。测试健康会话无需云端准备、没有 Codex 配置不重复运行脚本、插件失败不阻塞健康编辑器。按目标锁定和合并同一准备期间的权属查询，断线修复仍强制核验。运行全部 IDE 与 TerminalBridge 测试。
- [ ] 自动恢复。对 SSH 退出、上游握手失败、浏览器网络恢复添加受限且去重的修复触发。保留浏览器 origin、cookie、iframe 和未保存文档；禁止重放写请求及拼接未知 WebSocket 数据流。通过真实断开测试及模拟故障验证。
- [ ] 加载状态。前端区分连接就绪与编辑器加载；保留现有页面布局和其他正在进行的改动。验证加载、离线、恢复、后台标签页、多实例行为。
- [ ] 实测与交付。仅部署本任务相关文件，备份原文件，失败恢复；协调运行服务中已有编辑器，避免无提示重启。运行浏览器冷缓存/热缓存/新代理测速、编辑内容保留、文件读写/终端/插件可用性和持续连接测试。保存不含 token/password/cookie 的 JSON 测量结果。

## 验收

- 多次真实打开均记录后台准备、工作区出现和关键资源传输量；预热后的本机缓存不再从远端拉取 workbench.js。
- 健康会话重复打开目标为 10 秒以内；后台重建后目标为 20 秒以内。若实际网络不支持，继续定位剩余延迟，不以单元测试代替测速。
- 注入 SSH 退出和浏览器短暂离线后自动恢复，原未保存文档和 iframe 保留；长期连接观察及操作没有未恢复的断线。
- 不降低任务权属、站点隔离、localhost 访问控制与认证；不缓存用户文件、凭据、动态 HTML、插件 webview 内容或任意代理应用。
- 相关测试、浏览器验证、部署运行代码一致；未满足的项目保持待办。工作区原有未提交改动不覆盖，不自动提交它们。
