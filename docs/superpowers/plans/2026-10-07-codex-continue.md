# Codex 启动自动 Continue

用户要求启动时自动通过 Codex 欢迎页。此前固定代理端口只保留浏览器中的确认状态，新的浏览器存储空间仍显示欢迎页。

在已有 `ide-frame-status.js` 中复用面板检查：仅同源、可见、`openai.chatgpt` webview 内，固定版 26.5908.31748 的完整欢迎文案、两个帮助链接、三个列表项及唯一启用的 Continue 按钮全部匹配时点击一次。含输入、权限选择或对话框的页面不处理。插件原有点击处理保存状态，不写入内部存储。每个文档最多点击一次；更新后的插件文案若变化则保留手动操作。

独立打开编辑器也执行欢迎检查；向父页面发送加载状态仅在内嵌时执行。沿用每两秒检查和后台页面暂停，无新增轮询器。

验证：
- `scripts/ide_continue_smoke.py`：先复现直接打开不继续，再验证 15 个本地用例通过，覆盖独立/内嵌、刷新、单次点击以及其他按钮、权限、对话框、聊天输入、隐藏框架、不同扩展、跨域框架和变化文案/链接。
- `scripts/ide_experience_smoke.py`：原有后台配置状态、退避、面板加载、专注模式、草稿和来源校验回归通过。
- Node 语法检查、`git diff --check` 通过。
- 独立复审无问题。
- 实机独立编辑器自动离开欢迎页并出现 Codex 输入框，未手动点击 Continue；刷新独立页、重开内嵌页后，两处均确认输入框数量 1、Continue 数量 0。截图：`data/codex-auto-continue-live.jpg`。

部署仅替换桌面运行目录的 `static/ide-frame-status.js`，备份和哈希记录于忽略目录 `data/releases/before-codex-continue-1007/`。无需服务重启。已打开的页面需重新加载脚本。
