# CCI 站内编辑器实施计划

> 使用 writing-plans、test-driven-development 和 subagent-driven-development 完成实现与独立复核；用户已授权直接开发，无需再次确认范围。

**目标：** 两站点本人名称含 charles 的运行 CCI 支持桌面端免登录站内 code-server，ACP 和手机不显示入口。

**架构：** 通过现有 IAM 认证终端在精确选中的 CCI 容器启动固定版本 code-server，通过本机已配置的 SSH 连接转发至 CCI 内网地址。编辑器保留随机密码，后台登录；浏览器通过带一次性入口票据、HttpOnly 会话 Cookie 的独立 loopback 代理访问，主站 `/ide` 用 iframe 内嵌该独立 origin。代码服务和监控 API 不共用 origin。

**技术：** FastAPI、HTTPX streaming、websockets、系统 OpenSSH、code-server 4.139.1 Linux amd64，归档 SHA256 `53029be6c5781b7bca49b815fcc9a2a3fc111813ad8c9965b2c0f0d2985a0674`。

## 验证基础

- 茅山旺两个 CCI 的实例 IPv4、名称和主容器通过官方 API 获取。
- 经 IAM 终端核实容器身份、Linux x86_64、Python3，以及归档下载 HTTP 200。
- 本机 `maoshanwangtech` SSH 别名可通过现有密钥登录；使用已有 known_hosts 严格验证代理主机身份。
- SSH 主机可连接两个 CCI 内网的 22 端口，SSH 本地转发能抵达目标。CCI sshd 存在 MaxStartups 拒绝，因此使用 IAM 终端启动编辑器、SSH 直接转发编辑器 HTTP 端口，不更改 sshd。
- SenseCore 当前没有运行 CCI，只能进行模拟测试；使用独立的 SSH 别名配置。

## 1. 远端安装与管理

创建 `server/cci_ide.py`、`server/ide_bootstrap.py` 和相关测试。

- 先写测试：拒绝 ACP、非本人、已停止、错误实例、非 IPv4；首次安装必须校验归档哈希；不得覆盖现有用户配置。
- 复用 `TerminalBridge.targets/open/read/write/disconnect` 进行认证与单次 Python 脚本执行，ASCII 随机边界提取 JSON，限制输出与超时，执行完成关闭该脚本的 Shell。
- 安装目录位于容器用户的专属 ilab 子目录；以文件锁串行安装；缓存固定版本，不更新系统包、训练启动命令或 AFS 文件。
- code-server 绑定该容器的内网地址随机高端口，密码为随机高熵值、配置文件 0600，启动前核对 hostname。进程使用独立日志和 PID 信息，复用健康实例，不杀死无关进程。
- 工作目录优先 `/workspace`，缺少时回退容器 HOME。只有首次创建编辑器用户设置时写入默认主题及启动页设置。
- SSH 子进程使用参数数组、BatchMode、StrictHostKeyChecking、已有 known_hosts；随机 loopback 监听端口，ExitOnForwardFailure、保活、退出清理。站点对应 `MONITOR_CCI_IDE_SSH_HOST` / `SENSECORE_CCI_IDE_SSH_HOST`，默认 `maoshanwangtech` / `sensecore`。

## 2. 独立 origin 的浏览器代理

创建 `server/ide_proxy.py` 和 `tests/test_ide_proxy.py`。

- 后台用随机密码向上游 `/login` 登录，Cookie 仅保存在后端 HTTP 客户端，不返回浏览器。
- 临时代理只绑定 127.0.0.1；验证 Host、Origin、HttpOnly 会话 Cookie；入口票据一次性且短期有效。
- HTTP 流式转发请求与响应，移除 hop-by-hop、调用者 Cookie/Authorization 和上游 Set-Cookie；不跟随上游跳转，仅重写指向自身上游的绝对地址。
- WebSocket 转发二进制、文本和关闭事件，校验同源、Cookie、子协议；断开任一端后释放另一端。
- iframe 只允许实际监控 origin 嵌入。关闭主服务时释放代理和 SSH 连接；无人连接一段时间后释放本地资源，不停止训练任务。
- 测试未授权请求、过期/重复票据、错误 Origin/Host、密码不泄漏、HTTP 内容、重定向、WebSocket 往返及关闭。

## 3. API 与桌面入口

修改 `server/main.py`，创建 `server/ide_routes.py`；前端修改 `static/index.html`、`static/acp.js`、`static/mobile.css`，新建 `static/ide.html`、`static/ide.js`、`static/ide.css`。

API 合约，全部 POST 复用 X-Monitor-Request 和 X-Monitor-Site：

```json
{"endpoint":"/api/cci/ide/targets","body":{"task_id":"CCI:app-id"},"response":{"request_id":"opaque"}}
{"endpoint":"/api/cci/ide/open","body":{"task_id":"CCI:app-id","instance":"pod-id","container":"main"},"response":{"request_id":"opaque"}}
{"endpoint":"/api/cci/ide/status","body":{"request_id":"opaque"},"pending":{"pending":true,"message":"正在准备编辑器"},"done":{"pending":false,"result":{"site":"maoshanwang","task_id":"CCI:app-id","port":12345,"ticket":"opaque","name":"charles task","instance":"pod-id","container":"main"}}}
```

- targets 完成结果与 CCI terminal targets 合约一致。出错 status 返回 `pending:false,error`，不包含凭据或原始 SSH 日志。
- 新入口 `进入 VS Code` 只对运行、charles、CCI 显示，链接 `/ide?site=...&task_id=...`，桌面新标签页。
- 手机 UA、窄屏和 APK 隐藏按钮；直接打开启动页也不启动远端服务。现有手机网关不开放 IDE API，无需修改 APK。
- `/ide` 页面自动发现实例，单实例自动准备、多实例选择后准备；显示进度、错误和重试，成功 iframe 访问同主机名不同端口 `/_ilab_open/<ticket>`。
- 浏览器不处理 code-server 密码。保留站点、任务名、返回监控和重新打开；iframe 占满剩余视口。
