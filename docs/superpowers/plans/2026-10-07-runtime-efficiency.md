# 全站运行效率优化计划

**Goal:** 减少后台采集的串行等待、保持页面状态刷新独立，并降低密集列表的格式化开销。

**Architecture:** 沿用既有采集器、请求取消机制和原生页面脚本。只调整已确认的等待依赖与对象复用，不增加缓存时效或降低采集频率。

**Tech Stack:** Python asyncio、httpx、pytest、原生 JavaScript、Intl、Node 行为验证与浏览器模拟验收。

## 约束与基线

- 保留当前 TokenHub 零消费修复；视觉草案不属于本次实施。
- 保留鉴权隔离、失败旧值、请求取消和原有并发限制。
- 既有前端效率检查 50 项通过。
- 20 任务、8 worker、38,400 采样的原有基准：重复保存中位数 63.659ms，状态 API 0.945ms，历史 API 3.323ms。这些仅是环境基线，并非本轮主要优化指标。
