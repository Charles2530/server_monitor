# 队列管理与 ACP 利用率实施

目标：侧边栏与页面标题改为“队列管理”，保留 `#waiting`；原区块标题改为“等待队列”，下方新增全用户、运行中 ACP 的 GPU 利用率升序队列。

## 方案与边界

复用个人监控采集会把全用户指标请求加入关键路径；本次采用与任务历史相同的独立后台快照服务。仅进入队列页面后读取，60 秒缓存，单站点最多三个任务同时读取 GPU。不读取 CPU、内存、显存，不保存其他用户的历史曲线，不添加停止、Shell 或编辑器操作。

任务列表使用当前站点 `trainingJobs` 的 `RUNNING` 过滤和分页，校验工作空间后只保留展示字段。GPU 使用现有 ACP `WorkerGpuUtilTotal` 面板，查询最近五分钟。沿用各 Worker/GPU 最新有效值的平均口径，Worker 缺失、过期、越界或失败显示未知并排末尾。0% 为有效值。CPU 任务显示未配置 GPU。列表失败保留旧列表并明确标注；旧列表不继续当作当前有效排名。

## 实施步骤

1. 新增 `tests/test_utilization_queue.py`，先运行确认缺少模块、路由与手机网关白名单而失败。覆盖双站点、全用户范围、分页、升序、0/未知、Worker 缺失、脱敏、缓存去重、取消清理和只读边界。
2. 新增 `server/utilization_queue.py`，在 `server/main.py` 为每站点初始化服务并注册 `GET /api/utilization-queue`，应用关闭时清理任务。将此 GET 加入手机网关只读白名单。
3. 精确修改 `static/index.html` 的导航、原队列标题与容器，新增利用率表；保留已有 TokenHub 修改。新增独立 JS/CSS，复用表格与移动端卡片布局；页面离开或隐藏时取消前端请求与计时器。
4. 更新 `static/navigation.js` 页面标题与说明；运行后端测试，使用模拟数据与真实只读快照检查排序、空值和不同屏宽。运行完整回归与 `git diff --check`。

## 验收

- “队列管理”内同时出现“等待队列”“利用率队列”，其他路由不显示这些区块。
- 不含 CCI、排队或已结束 ACP；包含其他用户运行 ACP，按利用率升序，未知置末。
- 只读跳转可用，双站点不串数据，其他用户不获得站内写操作入口。
- 桌面、手机布局无页面横向溢出；现有个人监控范围与 TokenHub 修改保留。
- 列表/指标错误有说明，后台任务可清理，页面轮询不产生重叠刷新。
