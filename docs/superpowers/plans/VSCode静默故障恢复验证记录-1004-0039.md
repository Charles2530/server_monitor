# VS Code 静默故障恢复验证记录

## 结论

此前已部署的连接优化继续生效，线上热启动实测 8.6 秒、完整重建约 30 秒。本轮只在 8876 隔离服务测试，没有再次重启 8766 生产服务。新增两文件恢复补丁已暂存，尚未部署。完整重建低于 20 秒和快速静默故障恢复均未达成。

## 故障实测

仅暂停隔离服务自身的 SSH 进程，模拟进程存活但停止传输；180 秒保护恢复未触发，系统提前建立了新 SSH。未改变云端任务或远端项目文件。

| 场景 | 从故障注入到恢复 | 关键证据 |
| --- | ---: | --- |
| 已部署版本，包装页与编辑器同时打开 | 62.53 秒 | 新 SSH、同一代理端口，最终 4 条连接；草稿可继续编辑、终端回显成功 |
| 候选，包装页定时恢复先获得锁 | 59.97 秒 | 健康检查仍为 16.315 秒；最终 4 条连接 |
| 候选，只保留直接编辑器页面 | 68.80 秒 | 代理触发健康检查 8.006 秒，恢复操作本身 19.453 秒；最终 2 条连接 |

最后两次测试使用同一未保存草稿，两次恢复后分别追加 FIRST_RECOVERY_EDIT_OK 和 SECOND_RECOVERY_EDIT_OK，最后新建终端得到 CANDIDATE_REMOTE_EXEC_OK 回显。截图：`data/ide-stall-candidate-verified.jpg`。

数据仅证明代理触发路径少一次 8 秒健康检查，不能声称整体恢复时间减少 8 秒。故障发现、浏览器重连节奏和云端网络仍主导总时延；样本不构成稳定性能保证。本轮完整重建另一次样本为 33.7 秒。

## 修改范围

- `server/cci_ide.py`：代理已观察到当前连接失败时仅再确认一次健康状态；普通打开和定时恢复仍做两次检查。锁内核对失败时的上游地址，过期信号不能削减新连接的检查。重新建连前继续校验权属，保留代理端口和浏览器认证。
- `server/ide_proxy.py`：HTTP 与 WebSocket 尝试前记录失败所属上游；转发阶段保留同一地址，并传给修复回调。
- `tests/test_ide_latency.py`、`tests/test_ide_transport_repair.py`：覆盖一次确认、正常连接不替换、旧失败排队期间连接已更换、请求尚未完成时上游变化。
- `tests/test_cci_ide.py`：本地集成测试客户端设置 trust_env=False，避免系统 HTTP 代理使 localhost 检查偶发超时；生产客户端原本已使用此设置。

## 验证

全量 `.venv/bin/python -m pytest -q tests --tb=short`：482 项通过，5 条已有依赖弃用警告。随后加强失败所属上游断言，相关 25 项通过。UI smoke 通过，使用模拟 API、不调用云端。独立审查发现的过期失败信号问题已修复，复审无阻断项。

曾有一次全量测试因测试客户端使用环境代理导致 localhost ReadTimeout；修正客户端后重跑全量通过。未将失败结果隐去。

## 候选与生产边界

`data/ide-recovery-candidate/manifest.json` 记录生产基线与候选 SHA256；`recovery.patch` 为相对于当前生产版本的两文件差异。候选文件为 `server/cci_ide.py` 和 `server/ide_proxy.py`。生产文件哈希仍符合基线；两个站点状态接口 HTTP 200、connected=true。旧部署候选保留不动。

应用候选需要重启本机监控，当前代理监听会消失，需先保存当前编辑器内容；本轮没有执行切换。前述测试能证明短时故障下草稿保留，不能保证本机进程重启、容器销毁或长期断网时的未保存内容安全。
