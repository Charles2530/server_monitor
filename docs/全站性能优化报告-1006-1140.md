# 全站性能优化报告

版本时间：2026-10-06（北京时间）。当前状态：实现及验证完成，发布包已冻结，尚未切换生产服务。

## 范围与结论

排查覆盖资源总览、运行任务与历史曲线、ACP 操作、等待及运行队列、存储、任务历史、日志、TokenHub、Terminal、VS Code 和手机网关。此次针对确认的性能问题修改；已有按需加载、背压、鉴权和状态保护的路径保持原有语义。

主要问题是静态资源重复完整传输、独立云数据源串行等待、历史查询缺少组合索引、页面不可见时仍刷新，以及重复历史/TokenHub 请求。没有将普通 API 的短时延归因为 SQLite 或网络，也没有用长期缓存掩盖数据更新。

## 修改

| 路径 | 改动与作用 |
| --- | --- |
| server/http_assets.py、server/main.py | 静态资源 gzip 压缩及私有缓存重新验证；弱 ETag 和 Vary 区分编码；动态 API 保持 no-store |
| server/mobile_gateway.py、scripts/mobile_host.py | 鉴权后转发静态压缩流与 304，部署时包含新增依赖；设备撤销仍先于缓存判断 |
| server/collector.py | 五个独立列表并行读取；汇总顺序、权限、部分失败和取消清理保持原语义 |
| server/store.py | 新增 samples(task,timestamp) 索引，避免短时间窗口扫描该任务所有历史 |
| server/task_logs.py | 有大小上限的日志 JSON、Base64 与清洗放入线程，减少阻塞其他异步请求 |
| server/tokenhub.py | 同账户 generation 的重叠刷新共享一次任务；保留账号切换、取消与关闭边界 |
| static/app.js、static/mobile.js | 相同任务、时间范围、快照只读一次曲线；取消过期读取；手机仅详情可见时读取 |
| static/storage.js、static/task-history.js、static/tokenhub.js | 页面隐藏时取消无效读取并停止轮询；恢复可见后更新 |
| static/acp.js | 隐藏等待队列不重建 DOM；数据及操作状态相同时跳过重复重绘，继续检查过期权限 |

Terminal 已有输入批处理、输出背压与 resize 合并，本轮不改变会话行为。之前部署的 VS Code 优化保留。运行队列已有按需刷新，本轮保留排序、创建时间、运行时长和“仅看我的任务”。没有执行云任务创建、停止、释放或重启来测试。

## 测量证据与边界

候选服务真实 HTTP 字节数：

| 静态文件 | 原始字节 | gzip 字节 | 减少 |
| --- | ---: | ---: | ---: |
| ECharts | 1,121,883 | 373,382 | 66.7% |
| Tabler CSS | 635,394 | 82,550 | 87.0% |
| app.js | 34,344 | 10,220 | 70.2% |

缓存重新验证实际返回 304、无响应正文。策略为 private, no-cache，需要检查版本，不使用可能长期过期的静态缓存。范围请求不压缩；测试包含 gzip;q=0、非法 q、大小写编码及通配符。

测试夹具测量：五项各延迟 20ms 的独立读取从中位数 105.9ms 降至 21.9ms；403,200 行历史、返回 2,400 行的查询从 18.5ms 降至 2.0ms。它们表示算法改善，不是线上端到端加速承诺。三个同时 TokenHub 强刷的上游读取由 15 次降至 5 次；未加入持久 HTTP 客户端。

复制生产数据库构建索引的首次初始化耗时分别约 148ms、30ms；真实索引占用会随数据增长。原数据库未在验证阶段修改。

真实浏览器：390px 手机列表进入后历史请求为 0；打开详情后历史请求成功（一次观测约 7ms），图表可见，返回列表恢复正常。桌面运行任务、范围切换、存储列表、177 条历史筛选、等待/运行队列、TokenHub 趋势及密钥列表读取均验证。候选环境的普通 API 只读转发当前生产，历史使用复制数据库；不把转发读数当作优化后的生产性能。
