# 任务切换与终端传输优化报告

本轮减少任务卡片重复创建与 Terminal 输出编码开销。精确提交快照、运行候选、真实浏览器和本地 PTY 验证已完成；正在运行的服务尚未切换。

## 修改与收益

| 路径 | 原因与修改 | 验证结果 |
| --- | --- | --- |
| 选择任务、筛选列表 | 原先每次重建全部可见卡片。现在复用内容未变化的卡片，选择只更新样式、aria-pressed 和底部提示；单条指标变化只替换对应卡片。 | VM 夹具中，40 张卡片连续切换三次，创建节点 4683 → 0，全列表替换 3 → 0。 |
| 来源错误提示 | 原先仅来源状态变化、任务数据相同时可能不更新卡片告警。 | 纳入 CCI／ACP 来源状态变化检测；失败与恢复测试通过。 |
| Terminal 输出 | 原先每个云端小帧分别 Base64 编码并产生 JSON 数组项。现在将当前缓冲字节按最多 64 KiB 的输出块编码。 | 4096 个 16 字节帧，共 64 KiB，编码次数和输出块数均从 4096 → 1；紧凑 JSON 从 110675 → 87470 字节。 |

上述操作次数和字节数来自固定夹具，不能作为生产页面或网络速度的提升比例。真实浏览器验证使用本地模拟 API；本地终端验证使用隔离 PTY 和 tmux，没有连接真实云会话。

## 保留的行为与边界

- 卡片缓存仅保留当前可见项；任务增删、重排、搜索、空列表及恢复均正常更新。
- 事件闭包仅保存任务 ID，详情从当前快照读取；重复点击仍可重试失败的历史请求。
- Terminal 保留原始字节顺序、原始帧游标、输入确认序号和用户隔离。收到 ACK 后才释放原始帧，重复读取与部分 ACK 语义不变。
- 合批仅影响响应编码。新增原始字节拼接缓冲最多 1 MiB；此限制不包括已有帧、Base64 字符串和 JSON 的内存。
- 已检查浏览器终端、HTTP 兼容连接和 CCI IDE 消费路径，没有逐输出块对应帧序号的依赖。
