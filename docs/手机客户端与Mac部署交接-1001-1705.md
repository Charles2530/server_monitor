# Android 客户端与另一台 Mac 的部署交接

本文件面向接手部署的 AI 和用户。目标是让另一个常开 Mac 运行监控，手机安装单个 APK，经 App 内嵌 Tailscale 访问这台 Mac。当前项目仍独立运行于本机 127.0.0.1:8766；本轮不替换原站点、不部署到公网、不修改真实云任务。

## 先读的边界

- 原型 Android 客户端只支持 Android 8+ ARM64；手机首次需要 Tailscale 官方登录，并与电脑所在的同一个 tailnet 连接。首次配对还需在电脑批准设备。
- 未使用 Android VpnService，不要求安装第二个 Tailscale App；能否在用户实际 Android 版本、网络和省电策略下稳定运行，必须做真机验收。
- 不需要自购域名。电脑 Tailscale Serve 提供私有 HTTPS 的 `机器名.网络名.ts.net` 地址；不能使用公开的 Funnel。
- 网络认证和监控授权是两套独立身份：手机加入 tailnet 后，还须拿一次性配对码换设备 token，并在 Mac 批准。
- 未携带任何云 IAM 密码或长期 Tailscale auth key 到 APK；设备 token 使用 Android Keystore 加密，tsnet 状态在 App 的 no-backup 私有目录。
- 手机关闭/被系统回收不影响 Mac 采集。Mac 关机、休眠或断网会影响采集和远程访问。
- 所有云写操作复用现有后台验证和去重。联调先用只读权限。没有用户明确要求，不创建、停止、重启、释放重启任何真实任务。
- Git 同步的是代码。`data/` 中的历史、会话、配对数据库、工具链及 APK 构建产物不会跟随 Git。

## 目录与协议

| 文件/目录 | 职责 |
|---|---|
| `server/mobile_access.py` | 一次性配对码、设备审批、撤销、哈希凭证、有效期 |
| `server/mobile_gateway.py` | 8767 回环网关，显式路径/方法白名单，固定转发到 8766 |
| `server/mobile_admin.py` | 本机管理 CLI，远端不开放管理接口 |
| `scripts/mobile_host.py` | 独立 macOS LaunchAgent 的安装、状态、停止与移除 |
| `mobile/tunnel` | Go tsnet/gomobile 模块、Android 进程内认证代理和测试 |
| `mobile/android` | Android Java/WebView App、原生网络接口与切换事件、进程级连接实例、加密保存与扫码配对 |
| `mobile/build_android.sh` | 固定依赖的 ARM64 调试 APK 构建 |
| `scripts/mobile_gateway_smoke.py` | 只读验证网关访问已有实时后台 |

数据流：APK WebView → 手机 127.0.0.1 固定随机端口 → Go 内嵌 tsnet → Mac Tailscale Serve HTTPS → Mac 127.0.0.1:8767 网关 → Mac 127.0.0.1:8766 原后台。

网关每个设备数据库持久化一个独立 host_id。手机按网关地址与 host_id 的组合分别保存随机端口，同一主机后续重用相同 WebView origin，保留原网页 localStorage 中待确认操作 ID；端口被占用时不自动切换新 origin。每次打开网页使用新的一次性启动票据换 HttpOnly Cookie。局部端口和 Cookie 都不是远程身份；仅原生模块持有网关 token。

网关路由：

- `GET /health`：不含敏感数据的存活检查。
- `POST /mobile/pair`：JSON `{ticket,name}`；兑换后返回 `{device_id,token,host_id,state:"pending"}`。
- `GET /mobile/status`：Bearer token 查询审批状态，pending 也可访问。
- 业务 API、静态资源、首页和 `/terminal`：必须已批准。写操作还要求 `can_write=1`。
- `Authorization`、Cookie、Origin 和来源 Host 不转发给原后台。网关自己构造固定 loopback 请求；无任意目标 URL 代理。
- 远端没有批准或撤销接口；只允许 Mac 本地 CLI 管理。
- 配对码有效 5 分钟，限用一次；待审批设备有效 10 分钟；批准后有效 90 天，可立即撤销。过期后需重新配对。

## 目标 Mac：主监控先正常运行

在目标 Mac 的仓库根目录执行，不要复制开发电脑的绝对路径：

```bash
./setup.sh
.venv/bin/python -m pytest tests -q
.venv/bin/python scripts/deploy_launchagent.py
./status.sh
curl --fail http://127.0.0.1:8766/api/state
```

如果这台 Mac 已经部署过，应先检查现有进程、未完成操作与当前版本，再按原部署流程更新。部署主监控会重启监控采集服务；手机网关的安装不会重启它。

本版 `static/acp.js` 增加了移动授权失效时的请求恢复保护，必须与网关一起部署；安装脚本会拒绝未包含此保护的旧页面。

主监控运行目录为 `~/Library/Application Support/CharlesCloudMonitor`。IAM 配置按本仓库既有方式使用；新机器重新生成云会话。不要在回复、日志、截图或公开 issue 输出 `.env` 内容、token、完整启动命令中的秘密。

若需要迁移历史，先停止源采集或使用 SQLite backup 得到一致备份，并确认目标数据不会被覆盖；这不是运行手机客户端的前置条件。

## 目标 Mac：安装独立手机网关

```bash
.venv/bin/python -m pip install -r requirements-mobile.lock
.venv/bin/python scripts/mobile_host.py install
.venv/bin/python scripts/mobile_host.py status
.venv/bin/python scripts/mobile_gateway_smoke.py
```

网关运行目录为 `~/Library/Application Support/CharlesCloudMonitorMobile`，凭证数据库在其中的 `data/devices.sqlite3`。网关依赖已部署主监控的 Python 环境，仅复制三个 `mobile_*.py` 模块，不更改原任务数据库。

LaunchAgent 名称为 `charles.server-monitor-mobile`，监听 `127.0.0.1:8767`，使用独立日志。它在用户登录后启动；不等于 FileVault 解锁前或无人登录时自动运行。不要擅自改用户电源、登录或磁盘加密配置。

## 目标 Mac：配置 Tailscale

由用户安装并登录官方 macOS Tailscale 客户端。可用 CLI 若不在 PATH，可使用 `/Applications/Tailscale.app/Contents/MacOS/Tailscale`。

先检查已有状态与配置：

```bash
tailscale status
tailscale serve status
```

确认本机没有需要保留的 HTTPS 443 Serve 配置后，建立私网入口：

```bash
tailscale serve --bg --https=443 http://127.0.0.1:8767
tailscale serve status
```

不要执行 Funnel；不要覆盖现有 Serve 服务。首次可能需要用户在 Tailscale 管理界面启用 HTTPS / MagicDNS 或批准设备，按 CLI 的实际提示处理。不要自动改已有 tailnet ACL。若网络策略需要增加权限，只开放本手机访问本 Mac 的 443。

保存实际输出的 HTTPS 根地址，下文用 `https://your-mac.your-tailnet.ts.net` 表示，必须替换为实际地址；客户端不接受普通公网域名、HTTP、路径前缀或非 443 端口。

## 构建 APK

推荐使用 Android Studio 的 SDK Manager 和 JBR/JDK。构建环境要求：

- Go 1.27.1；模块同时固定 Tailscale v1.102.5 与 x/mobile 版本，并跟踪 go.sum。
- JDK 17 或兼容的 Android Studio JBR。
- Android SDK platform 35、platform-tools、build-tools 35.0.0、NDK 27.2.12479018。
- Gradle wrapper 固定 8.11.1，分发包有 SHA256 校验；AGP 固定 8.9.2。

已有 Android 命令行工具时，可安装指定组件：

```bash
sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0" "ndk;27.2.12479018"
```

确认环境路径后执行；以下路径仅适用于按默认位置安装的 macOS Android Studio：

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
./mobile/build_android.sh
```

若 JDK 在其他目录，应使用实际 JDK 的 `Contents/Home`。`go` 必须已在 PATH。构建会联网下载固定依赖，并在 `mobile/tunnel/build`、`mobile/android/app/libs`、Android build 与 Gradle 缓存中生成文件，不修改全局 SDK 配置。

APK 输出：`mobile/android/app/build/outputs/apk/debug/app-debug.apk`。

这是个人验证用 debug 包。换电脑构建默认调试签名可能不同；为保留手机配对和待确认操作记录，后续覆盖安装应使用同一个签名。正式长期使用前配置独立发布签名，将签名文件放在 Git 外；不自动卸载旧 App 来解决签名冲突。

## 手机首次使用

1. 安装 APK，在 App 内点击首次 Tailscale 登录，再打开网络授权页面，登录与 Mac 相同的 tailnet。回到 App，网络状态应为 Running。
2. 在 Mac 仓库目录生成新的配对文件和二维码：

```bash
PAIR_FILE="data/mobile-pair-$(date +%Y%m%d-%H%M%S).json"
.venv/bin/python scripts/mobile_host.py admin pair \
  --url https://your-mac.your-tailnet.ts.net \
  --out "$PAIR_FILE" --qr
open "${PAIR_FILE%.json}.svg"
```

3. 手机扫描二维码后点击配对。没有相机时，可以把生成文件的 JSON 内容粘贴到 App；不要贴到公共聊天或日志。
4. App 显示等待审批及设备 ID。Mac 上执行：

```bash
.venv/bin/python scripts/mobile_host.py admin list
.venv/bin/python scripts/mobile_host.py admin approve DEVICE_ID
```

将 DEVICE_ID 换成刚刚手机显示的值，核对名称；不要批准未知设备。默认只有查看权限。

5. 手机进入监控，切换两个站点，验证资源、任务、队列、存储、历史和日志。只有用户需要远程创建/停止任务时才升级权限：

```bash
.venv/bin/python scripts/mobile_host.py admin approve DEVICE_ID --allow-writes
```

手机凭证过期或需要更新时，可直接扫描同一主机的新配对码并重新配对，保留待确认操作；不要先使用“更换监控电脑”清理记录。

手机没有云平台浏览器会话时，官方任务链接与 Terminal 可能要求登录。App 不把电脑云 Cookie 复制到手机，也未实现终端会话代理。

## 更换 Mac 与撤销

新 Mac 单独部署网关、配置 Serve，并生成新配对码。手机设置选择“更换监控电脑”，再与新电脑配对。更换前先核对所有结果未知的操作；更换会清理旧网页存储，以避免把旧主机的操作 ID 用在新后台。

旧 Mac 撤销手机：

```bash
.venv/bin/python scripts/mobile_host.py admin revoke DEVICE_ID
```

更换电脑不会自动把旧 Mac 的数据库或配对权限带过去，也不会自动撤销旧权限。

## 验收清单

### 可自动运行

```bash
.venv/bin/python -m pytest tests -q
.venv/bin/python scripts/mobile_gateway_smoke.py
.venv/bin/python scripts/mobile_recovery_smoke.py
(cd mobile/tunnel && go test -race ./... && go vet ./...)
./mobile/build_android.sh
```

### 必须在用户手机和目标 Mac 上运行

- 手机关闭 Wi-Fi，用移动网络访问 Mac；Mac 与手机不在一个物理网络。
- 全新安装 APK，不另装官方 Tailscale 手机 App，首次网络授权和扫码配对可完成。
- 未批准和已撤销设备不能访问业务数据；只读手机提交写请求返回 403。
- 两站点的任务和资源对应正确，网络断开提示离线，重连后正常刷新。
- 手机 Wi-Fi/移动网络切换、锁屏后回前台、强制结束进程再打开均验证。
- App 重开后本地地址不变；历史待确认操作 ID 没有丢失。不要用真实云写操作验证重试；先使用模拟 API 或测试环境。
- CCI/ACP Terminal 能选择目标并打开官方页面；官方登录与键盘操作单独验收。
- 重启目标 Mac 并登录后，两项 LaunchAgent 恢复。未登录状态不作自动启动承诺。
- 如 tsnet 在手机上失败，保存脱敏错误和设备/网络信息；不能把编译通过写成跨网成功。是否改用系统 VPN 或官方 Tailscale App，先与用户确认体验变化。

## 停止、更新与回滚

```bash
.venv/bin/python scripts/mobile_host.py stop
.venv/bin/python scripts/mobile_host.py uninstall
```

`stop` 停止当前网关，plist 保留，下次登录可重启；`uninstall` 同时移除自动启动，保留配对数据库。需要完整关闭入口时，在确认是本应用独占的 Serve 443 配置后执行 `tailscale serve --bg --https=443 off`，不清空其他服务。

Git 更新后重新运行 `mobile_host.py install` 更新网关；原监控功能更新仍按原部署脚本处理。回滚网关使用先前版本源码重新 install，保留当前 devices.sqlite3，不恢复旧凭证数据库。设备撤销记录和任务操作数据库都不可随意回滚。

## 可直接交给接手 AI 的任务

> 阅读本文件和仓库 README。先检查目标 Mac 的现有监控部署、Tailscale 状态与 Serve 配置，再部署主监控和独立手机网关。不要输出凭证，不要覆盖已有 Serve 配置，不要执行真实云任务写操作。按文档构建 Android ARM64 APK，并协助用户完成首次 Tailscale 登录、一次性配对和只读设备批准。手机关闭 Wi-Fi，用移动网络验证两站点访问、断网恢复和设备撤销。记录每项真实验收结果，区分构建成功和跨网成功；需要用户实际登录或操作手机时明确说明当前步骤。未通过的项目继续排查，不伪造完成状态。
