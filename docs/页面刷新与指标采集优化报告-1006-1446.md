# 页面刷新与指标采集优化报告

本轮优化存储页、历史任务页和后端指标采集。代码、精确提交快照与运行候选已验证；运行服务尚未切换，因此这些收益尚未在生产页面生效。

## 原因与修改

| 路径 | 原有开销 | 修改与离线证据 |
| --- | --- | --- |
| 存储刷新 | 返回相同数据仍重建表格、容量汇总和分区选项 | 比较当前可见数据，复用未变化的节点。40 个存储卷连续三次相同刷新，创建节点从 1845 个降为 0，三类重建次数各从 3 次降为 0。 |
| 历史任务刷新 | 后台读取期间每两秒刷新，当前页即使未变化也重建 | 只在当前页数据或空表提示变化时重建。25 行当前页连续三次相同刷新，创建节点从 1725 个降为 0，表格重建从 3 次降为 0。 |
| ACP Worker 指标检查 | 每个 Worker 都扫描整个指标曲线列表 | 每种指标先按 Worker 精确分组，再查对应曲线。200 个 Worker、800 条曲线的标签解析从 160,000 次降为 800 次。 |
| 监控信息首次读取 | 工作空间 UID 与租户监控站两个独立读取串行等待 | 同时启动读取，保持原有结果处理与缓存写入顺序。事件屏障测试验证两个站点均可重叠读取；缓存齐全时不发请求。 |

节点数来自执行真实页面脚本的 VM 行为夹具；标签解析次数来自后端隔离回归。这些是操作次数，不能换算为线上页面提速比例。本轮没有进行生产网络或真实浏览器端到端测速。

## 保留的行为

- 轮询周期和服务器请求次数不变，没有通过降低刷新频率换取性能。
- 页面时间、告警、来源错误、统计、分页和读取状态继续更新；数据变化时正常重建。
- 筛选、搜索、分区选项、挂载提示及历史任务重新启动按钮的目标参数保持一致。
- 渲染中途失败会清除签名，避免下次相同数据被误判为已完成渲染；恢复回归已验证。
- Worker 分组仍区分相近名称，保留多 GPU、零值、缺失、过期与 null 的处理；CCI 和 CPU-only 路径保持原语义。
- 首次读取同时启动，但按工作空间、监控站的原顺序检查错误和写缓存。失败或取消时回收自身所有读取任务，确保 HTTP 客户端关闭前清理完成。
- 多个日志请求共享同一读取器时，处理监控站结果前重新检查共享缓存，复用其他请求刚取得的有效结果。
